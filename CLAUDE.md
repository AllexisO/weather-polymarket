# weather-lab

Поиск честного преимущества (edge) на погодных маркетах Polymarket (48 городов, «Highest temperature»).
Оператор и единственный разработчик — Alex. **Реальных денег нет** — только виртуальные кошельки
(`/paper`). Всё, кроме погоды, — проект `polymarket-markets` (`/mnt/applications/docker/stacks/polymarket-markets`, порт 8094).
Главная модель — v3, кошелёк **`ml3`**.

**Подробности — открывать только когда нужно для задачи:**
- `docs/ARCHITECTURE.md` — схема, крон, скрипты → таблицы, модель, кошельки и их правила, сайт;
- `docs/PRD.md` — цель, метрики, порог реальных денег, **что уже проверено и не сработало** (смотреть перед новой идеей);
- `docs/DESIGN_SYSTEM.md` — цвета, компоненты, правила страниц (смотреть перед правкой шаблонов);
- `docs/CLAUDE_archive_*.md` — история решений и цифры.

## Как работать с Alex

- По-русски, коротко, простым языком. Результат — **в долларах через кошельки**, сравнение — доходность в %.
- Новая идея — **отдельным кошельком/вариантом**, не менять две вещи сразу.
- Не предлагать «подождать данных» или «закрыть направление» — искать методы. Про ML не говорить «нельзя».
- Решения о городах, ставках, платных API, резервных копиях, переносе проекта — за Alex.
- **Слишком хороший результат — сначала искать ошибку** (урок: +$7260 из протухших цен).
- Во внешние API не передавать личные данные. Git: github.com/AllexisO/weather-polymarket (**public** — без секретов и данных, `data/` и `.env` в .gitignore); коммиты и push по просьбе.
- Реальные деньги — только по прямому решению Alex и после порога из `docs/PRD.md`.

## ОБЯЗАТЕЛЬНО после любого изменения кода

**`./check.sh` — не заканчивать, пока не «ПРОВЕРКА ПРОЙДЕНА»** (сборка, колонки, прогон всех
кошельков в памяти, все страницы). Новая модель/кошелёк: сначала колонка (ensure_schema), потом
кошелёк. Меняешь правило кошелька — поправь `app/wallet_docs.py`. Меняешь устройство — поправь `docs/`.

## База

- SQLite `data/db/polymarket_lab.sqlite3` (~6 ГБ, WAL). Скрипты: `docker compose run --rm collector <скрипт>`.
- **Исследования — только на копии**: `docker compose run --rm -e JOB_TIMEOUT=0 -e POLY_LAB_DB=/data/research/research.sqlite3 collector ...`
  — долгие запросы к рабочей базе блокируют крон («database is locked»).
- Предел времени запуска — `JOB_TIMEOUT` (по умолчанию 40 мин); сторож `db_watchdog.sh`.
  В постоянно работающих процессах — короткие соединения и `rollback()` при ошибке.
- Open-Meteo: ~10 тыс. вызовов/сутки, крон тратит 5-6 тыс. — большие загрузки делить.

## Методология

1. Порог решения фиксируется числом ДО просмотра результата.
2. Подбор на одном периоде, проверка на другом; деньги — по настоящим сделкам (`poly_trades`), с комиссией.
3. Варианты модели сравнивать по среднему нескольких обучений (разброс ±0.015).
