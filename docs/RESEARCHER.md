# Недельный разбор модели — порядок работы

Раз в неделю, в воскресенье вечером (повторяющаяся заметка на /notes, плашка на всех страницах сайта).
Alex пишет Claude: «разбор недели». Цель — не отчёт, а **улучшение модели**: найти, где она ошибается
систематически, превратить это в то, что она сможет учесть при обучении, проверить и, если прошло, добавить.

Модель и так переобучается каждую ночь на всей истории, включая прошлую неделю: отдельные промахи она «видит» сама.
Разбор нужен для ПОВТОРЯЮЩИХСЯ ошибок, которые она сама не исправляет (город, тип погоды, уверенность рынка,
сторона промаха) — им нужен новый признак, поправка или другое правило ставок.

## Шаги

1. Свежая копия базы (~2 мин, крону не мешает):
   `sudo docker compose run --rm -e JOB_TIMEOUT=0 --entrypoint "nice -n 19 python" collector weather_research.py`
2. Разбор недели (конец — вчера или воскресенье):
   `sudo docker compose run --rm -e JOB_TIMEOUT=0 -e POLY_LAB_DB=/data/research/research.sqlite3 --entrypoint "nice -n 19 python" collector weather_week_review.py 2026-10-04 | tee data/research/reviews/2026-10-04.txt`
   Что смотреть: где смесь хуже рынка (уверенность рынка, °C/°F, города), систематический сдвиг v3 теплее/холоднее,
   самые дорогие ошибки — есть ли у них общее. В конце разбора — «почему ошиблась» (`weather_why.py`): честная
   модель без знания недели раскладывает каждый промах по признакам (что толкнуло не в ту сторону), плюс что
   случилось днём по METAR (облака, смена ветра, час максимума) против обычных дней. Сравнивать неделю с 4 неделями до неё: одна неделя — шум,
   то, что держится несколько недель, — повод проверять.
3. 1-3 гипотезы из разбора + очередь в `docs/RESEARCH_JOURNAL.md`; сверить с `docs/PRD.md` §10 (не повторять).
4. Проверка каждой — на копии, скрипт `app/weather_study_<коротко>.py`, **порог записать до прогона**:
   - модель: логошибка смеси лучше текущей на ≥ 0.015 (среднее 3 обучений, проверка по месяцам — август и сентябрь,
     оба лучше) и не хуже на свежих днях (после отметки в журнале);
   - правило ставок: плюс в обоих периодах (июль-авг по цене 08:00, с 21.08 по настоящим сделкам) и лучше текущего;
   - слишком хороший результат — сначала искать ошибку.
5. Прошло → Alex решает: новая версия модели / кошелёк отдельно (как v4, v4e — главная модель не меняется сразу).
   Не прошло → строка в `docs/PRD.md` §10.
6. Итог — в журнал (что нашли в разборе, что проверили, цифры), сдвинуть отметку свежих дней, заметка «сделано»
   (следующая на неделю вперёд создастся сама).
