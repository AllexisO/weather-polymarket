Суть проекта: цель, как меряем, пороги и что уже проверено. Сокращено 19.10 (решение Alex); **полная версия со всеми цифрами —

## 1. Задача

Найти **честное преимущество** на погодных маркетах Polymarket «Highest temperature in X»: ставки, которые приносят деньги
**после комиссии и по реальной цене исполнения**. Рынок очень точен (цена ≈ частота) — преимущество ищем только там, где модель
уверенно спорит с рынком, и подтверждаем настоящими сделками, а не историей цен.

## 2. Для кого

Один пользователь — Alex. Реальных денег нет, только виртуальные кошельки (`/paper`).

## 3. Как меряем успех

- **Доходность в % от поставленного** по кошельку (`/paper`) — главное; кошельки сравниваем по ней, не в долларах (старты разные).
- Число закрытых ставок — без него доходность шум.
- Точность (logloss, меньше — лучше) против рынка (`/training`).
- Слишком хороший результат — сначала ищем ошибку (урок: +$7260 из протухших цен).

## 4. Порог реальных денег

1. ≥ 150 закрытых ставок главной модели (`ml5` с 20.10; до этого `ml3`) — честный бумажный журнал.
2. Реальные заявки (py-clob-client) вхолостую — **идёт с 26.10** (`weather_real_dry.py`, таблица `real_dry`, /real).
3. Проверены пополнение и вывод USDC — Alex 26.10: положит $10 для пробы. 4. Доступность Polymarket — Молдовы нет в списке
   запрещённых стран (Alex 26.10).
5. **Прямое решение Alex.**

**Готовность счёта (29.10, вхолостую — `real_exec.py` в `weather_fast_dry.py`, таблица `real_ledger` в `data/db/fast_dry.sqlite3`):**
один счёт $100 на весь банк; (а) заявка собирается и подписывается в момент решения (утренние — сразу после решения холостой быстрой
службы, ml_day — опрос каждые 20 с), а не через час, как `weather_real_dry`; (б) деньги за выигрыш — на счёт только после гашения
(вхолостую — пометка; настоящее — после выбора кошелька); (в) сверка учёта со ставками (`weather_fast_dry.py --report`); (г) пределы
риска: ставка ≤ $5, новые ставки за сутки ≤ $100, убыток за сутки ≥ $40 → пауза, счёт < $60 → остановка (по октябрю не сработали бы).
**Не готово:** пробное пополнение и вывод USDC (Alex 29.10: ещё не ставил); кошелёк Polymarket (рекомендация — вход через почту,
ключ — «Export private key»); настоящее гашение и сверка с балансом и позициями Polymarket — после кошелька; ключ в ночной копии
(`env.backup`) — решить до настоящего ключа.

## 5. Что входит

- 48 городов (`weather_cities.py`), итог по METAR; выбор городов — решение Alex.
- Кошельки по $100 (свои старты — `weather_paper.START_BY_WALLET`), ставка $2, один вариант на город-день.
- Модели: v5 (главная с 20.10, `ml5`), v3 (`ml3`), v4/v4e, смеси с рынком, дневная `ml_day`, LLM, правила (`fav`, `no_cheap`, `techno`…), бот-мейкер.
- Честное исполнение: живой стакан, задержка, комиссия 0.05·p(1−p), минимум 5 долей.
- Сайт: результаты в долларах, сценарии «угадаем k из n → итог → шанс».

## 6. Что не входит

- Реальные деньги до порога п.4. Всё, кроме погоды (`polymarket-markets` удалён 09.10: спорт ≈ Pinnacle, Kalshi, новости — ничего).
- Платные API — только по решению Alex. Идеи из §10 — без новой идеи не повторяем.

## 7. Правила проверки идей

1. Новая идея — отдельный кошелёк/вариант; не менять две вещи сразу.
2. Порог — числом **до** просмотра результата.
3. Подбор на одном периоде, проверка на другом.
4. Деньги — по настоящим сделкам (`poly_trades`) с комиссией; покупка по цене продавца, не по последней сделке.
5. Версии модели — по среднему нескольких обучений (разброс ±0.015).
6. Исследования — только на копии базы.

## 8. Ограничения

- Open-Meteo ~10 тыс. вызовов/сутки (крон 5-6 тыс.). Polymarket Data API хранит сделки ~30 дней — собираем каждую ночь.
- SQLite ~6 ГБ, долгие запросы блокируют крон. Резервные копии — решение Alex.
- Лимит Gemini (agy) общий с живыми LLM-кошельками; недельный сброс ~24.10 02:00. OpenRouter — предоплата, пополняет Alex.
