# PRD — weather-lab

Что проект должен сделать, как считаем успех и где границы. Как устроен — `docs/ARCHITECTURE.md`,
правила работы — `CLAUDE.md`.

## 1. Задача

Найти **честное преимущество (edge)** на погодных маркетах Polymarket «Highest temperature in X»:
ставки, которые на длинной дистанции приносят деньги **после комиссии и по реальным ценам исполнения**.

Главная трудность: рынок очень точен (цена ≈ частота). Преимущество ищется только там, где модель
уверенно спорит с рынком, и подтверждается настоящими сделками, а не красивой историей цен.

## 2. Для кого

Один пользователь — Alex (оператор и разработчик). Реальных денег нет, только виртуальные кошельки.

## 3. Как считаем успех

| Метрика | Где смотреть | Почему именно она |
|---|---|---|
| **Доходность в % от поставленного** по кошельку | `/paper` | главное; кошельки сравниваются по ней, не в долларах (у `copy` другой старт) |
| Число закрытых ставок | `/paper` | без количества доходность — шум |
| Точность модели (logloss) против рынка | `/training` | модель должна быть не хуже рынка, иначе edge — случайность |
| «Насколько модель права»: выиграно против ожидаемого | `/paper?w=…` | честна ли модель в своих шансах |

Слишком хороший результат — сначала ищем ошибку (урок: +$7260 из протухших цен).

## 4. Порог перехода на реальные деньги

Все условия, записанные заранее:

1. **≥150 закрытых ставок** главной модели (`ml3`) — честный paper-лог.
   На 27.09.2026 — 13 закрытых.
2. Прогон реальных заявок (py-clob-client) вхолостую.
3. Проверены пополнение и вывод USDC.
4. Проверена доступность Polymarket.
5. **Прямое решение Alex.**

## 5. Что входит

- 48 городов (`weather_cities.py`), резолв по METAR. Выбор городов — решение Alex.
- Кошельки по $100 (`copy` — $300), ставка $2, один вариант в день на город.
- Модели: v3 (главная), v4, v4e, смеси с рынком, `copy` (повтор сильных трейдеров), `obs`, старые — для сравнения.
- Реалистичное исполнение: живой стакан, задержка, комиссия, минимум 5 долей.
- Сайт с понятными результатами в долларах: сценарии «угадаем k из n → итог → шанс».

## 6. Что не входит

- Реальные деньги (до порога из п. 4).
- Всё, кроме погоды, — проект `polymarket-markets` (порт 8094).
- Платные API — только по решению Alex.
- Идеи из п. 10 «Проверено и не сработало» — без новой идеи не повторяем.

## 7. Правила проверки идей

1. Новая идея — **отдельный кошелёк/вариант**; не менять две вещи сразу.
2. Порог решения фиксируется числом **до** просмотра результата.
3. Подбор на одном периоде, проверка на другом.
4. Деньги — по настоящим сделкам (`poly_trades`) с комиссией.
5. Варианты модели сравнивать по среднему нескольких обучений (переобучение колеблется ±0.015).
6. Исследования — только на копии базы.

## 8. Ограничения

- Open-Meteo: ~10 тыс. вызовов/сутки, крон тратит 5-6 тыс.
- Polymarket Data API хранит сделки ~30 дней — собираем каждую ночь, иначе потеряем.
- Одна база SQLite ~6 ГБ; долгие запросы блокируют крон.
- Резервных копий нет (скрипт готов, включение — решение Alex).

## 9. Следующие шаги

1. Живые результаты `ml3` против версий → порог из п. 4.
2. Ещё год истории (2024-06..2025-05) — перепроверить на октябре-ноябре.
3. Ансамбли — копим с 26.09 (ECMWF/GEFS/ICON), с 28.09 ещё AIFS/UKMO/GEM (212 вариантов). Архив Open-Meteo
   для ансамблей нечестный, поэтому только своё накопление. **Порог зафиксирован 28.09, до результата:**
   шанс корзины из доли вариантов ансамбля (смесь 35/65 с рынком, как у ml3_cal), логошибка на днях с 28.09:
   (а) 6 ансамблей лучше 3 на ≥ 0.015; (б) смесь лучше рынка на ≥ 0.015. Обе на ≥ 600 город-днях
   (первый взгляд ~12.10, решение ~28.10). Прошло (а)+(б) → признак в v3 отдельным вариантом/кошельком.
   Прогноз «за 2 дня» — загрузить и проверить.
4. Резервные копии — решение Alex.

## 10. Проверено и не сработало (не повторять без новой идеи)

- Гонка за замерами (рынок быстрее бесплатных METAR); маркет-мейкинг; nowcast днём.
- Соседние станции, разборы метеорологов (LLM), NBM, WeatherNext 2, ветер/облачность.
- Решение в 10:00 и накануне вечером — по сделкам хуже, чем в 08:00.
- Поправка шансов (Platt), вес свежим дням, влажность почвы и вчерашние осадки, свежая точность
  погодных моделей (окна 7/14 дней), цель = итог Polymarket, второй слой
  «выиграет ли вариант», движение рынка за ночь, несколько вариантов в городе, выбор городов.
- Повтор сильных трейдеров с задержкой — их преимущество в скорости; `copy` проверяет
  только покупки накануне.
- Ещё год истории (2024-06..2025-05) — смешанно, не принят (перепроверить на октябре-ноябре).
- Короткое окно обучения (28.09, `weather_study_window.py`, лог `data/research/study_window.log`; 8 недель
  авг-сент, учим до недели — проверяем неделю, 3 обучения): вся история 1.2202, 365 дн 1.2201, 180 дн 1.2242,
  90 дн 1.2332; деньги смеси в сентябре +$88 / +$58 / +$64 / +$34. Дрейфа нет — короткие окна выигрывают
  отдельные недели и проигрывают другие без тенденции. Обучение раз в сутки на всей истории — оставить;
  чаще (раз в 12 ч) бессмысленно: новые факты приходят раз в сутки. Видеокарта не нужна (23 тыс. строк, 4.5 мин).
- Вес свежим дням и 500 деревьев (28.09, `weather_study_ablation.py`, лог `data/research/study_ablation.log`, те же
  8 недель и 3 обучения): полураспад 120 дн −0.010, 300 дн −0.006, 500 деревьев −0.004 — порог 0.015 не прошёл никто;
  деньги смеси в сентябре: 120 дн +$42, 300 дн +$54, 500 деревьев +$140 (как сейчас +$88).
- Ablation (что даёт точность, логошибка к «как сейчас» 1.2202): без рынка +0.050, без прошлых ошибок +0.006,
  без METAR +0.002, без прогнозов отдельных моделей −0.003 (не нужны), только сырая погода +0.098.
  Главный источник — мнение рынка и сводные прогнозы; «сырая погода» без рынка в смеси хуже самого рынка.
  Калибровка уровней хорошая (факт ≤ «10%» в 12% дней, ≤ «90%» в 90%).
- Минимальная цена ставки 10/15/20¢ вместо 3¢ (28.09, `weather_study_minprice.py`, лог `data/research/study_minprice.log`):
  по заранее записанному правилу **не прошло** — на июле-августе (цена 08:00) лучший порог 3¢. Но в сентябре по
  настоящим сделкам 15¢ лучше 3¢ у обеих моделей (v3 +$121 против +$91, смесь +$117 / +46% против +$89 / +25%),
  а переоценка вариантов 5-15¢ на всём рынке есть в обоих периодах (июль-авг 10-15¢: цена 12.2%, сбылось 10.3%;
  сентябрь 5-10¢: 7.0% / 5.2%). Цена 08:00 для дешёвых вариантов ненадёжна (урок про протухшие цены).
- Быстрый платный METAR (27.09, 137 событий «вариант стал невозможен» за 22-25.09): рынок сдаётся в среднем
  за ~2 мин **до** времени замера, наш бесплатный METAR приходит через ~6 мин после — успели в 1 случае из 137.
  Даже METAR через 1 мин оставил бы ~$1600 оборота за 4 дня (верхняя граница, с конкурентами), через 5 мин — $288.
  Преимущество только у источников **быстрее METAR** (1-минутные ASOS в США, 10-минутные данные нацслужб).
- Бесплатные 10-минутные данные нацслужб (27.09; Хельсинки FMI, Мюнхен DWD, Токио JMA): FMI выкладывает
  за 1-2 мин, но METAR EFHK приходит в ту же минуту; JMA (7-8 мин) медленнее METAR, DWD (~30 мин) — сильно.
  Промежуточные замеры надёжны (19 из 19 подтвердил METAR), но в 17 случаях рынок уже стоял на 0-5¢ — +$1 за 4 дня.
