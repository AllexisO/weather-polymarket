# Полная проверка проекта

Что смотреть и в каком порядке, когда Alex просит «проверь всё». Ниже — что находили раньше: прежде чем искать новое,
убедиться, что старое не вернулось. Каждую новую проверку — дописать раздел сверху в «Журнал проверок».

## Как проверять

1. **Готовые проверки** (быстро, ничего не меняют):
   - `docker compose run --rm --entrypoint python collector data_tests.py` — 8 тестов данных (расчёт ставок, шансы, METAR, итоги);
   - `docker compose run --rm collector weather_audit.py` — ставки против правил и итогов (нарушения / внимание);
   - последний `data/logs/weather_night_check.log` и `weather_logic_check.log` — проверки утро/день/вечер и логика (пн/чт);
   - `./check.sh` — сборка, колонки, прогон кошельков в памяти, страницы.
2. **Падения скриптов** — `job_log` за 3 дня: `rc != 0` или `item_errors > 0`, смотреть `output`. Исправленное — `fixes.py`.
3. **Каждый кошелёк ставит** — `paper_trades` / `paper_obs_trades`: последняя ставка по кошельку, доля skip/nofill и причины
   (кошелёк без ставок 2+ дня — найти причину: правило, деньги, данные).
4. **Данные свежие** — `station_obs` по городам (обновляется раз в 6 ч), снимки 07-09 местного: все 47 городов, у всех моделей
   есть шансы; таблицы сделок Polymarket (`poly_trades_days`) — за позавчера.
5. **Правила Polymarket** — `logic_rules` (текст описания по городу): станция (ICAO в тексте = наш `icao` / `station_for`),
   источник, точность, округление, SPECI, граница дня. Изменилось — прогон по истории (CLAUDE.md, «ОБЯЗАТЕЛЬНО до первой ставки»).
6. **Ложные тревоги** — каждое «нарушение» проверить на самом Polymarket (`closedTime`, `umaResolutionStatus`), прежде чем чинить
   кошелёк: часто это задержка или спор на стороне Polymarket.
